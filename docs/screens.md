# 화면 흐름

> 화면 규칙의 근거는 `docs/decisions.md` 2·3절. 여기서는 6단계 각각의 상세와 전환 규칙을 정한다.
> 요청·응답 형태는 `docs/api.md`, 시트 열은 `docs/sheet-schema.md` 참조.

---

## 1. 6단계 흐름

```
로그인 → 분야 → 프로그램 → 일정표 → 목록·열람 (한 화면)
```

> 2026-10-07 변경: 처음에는 목록(카드) 화면을 거친 뒤 열람 모달을 여는 6단계였으나, 일정표 칸을 누르면 열람 화면이 바로 펼쳐지도록 목록과 열람을 한 화면으로 합쳤다(6·7절).

| 단계 | 건너뛰는 경우 |
|---|---|
| 분야 | 분야 코드로 로그인하면 해당 분야로 바로 이동. 운영진(STAFF) 코드만 분야 선택 화면을 거침 |
| 프로그램 | 없음. 항상 워크숍 · 심화 멘토링 · 겨울 심화캠프 중 선택 |

> 학생 작품은 시간대에 귀속되지 않아 프로그램 카드로 넣지 않는다. 검색 → 인물 상세를 통해서만 노출한다 (8절, `docs/decisions.md` 3절 "2026-09-17 결정").

라우팅은 해시 방식: `#/music/workshop/세션ID` (`docs/decisions.md` 2절).

---

## 2. 로그인 화면

- 입력: 접근코드, 이름
- `auth` 요청 → 성공 시 토큰을 `sessionStorage`에 저장하고 곧바로 `data` 요청 1회 → 응답을 브라우저에 캐시
- 성공 후 「접근코드」 탭의 첫 화면 값에 따라 분야 화면 또는 해당 분야로 이동
- 실패 시 오류코드별 안내 문구 표시 (`AUTH_INVALID` · `AUTH_EXPIRED` · `AUTH_LOCKED`)
- 새로고침 시 세션 유지, 탭을 닫으면 해제 (`sessionStorage` 특성)

**재활용**: 기존 `index.html`의 `convertHangulToEnglish()` — 한영 전환 없이 입력된 접근코드를 되돌리는 보정. 접근코드 검증 로직 자체는 가져오지 않음(관문이 담당).

---

## 3. 분야 선택 화면

- 대상: 운영진 코드로 로그인한 경우만
- 4개 분야 카드: 음악 · 무용 · 전통예술 · 미술
- 분야 코드로 로그인한 이용자도 상단바를 통해 언제든 다른 분야로 이동 가능 (제한 없음, `docs/decisions.md` "분야 이동")

---

## 4. 프로그램 선택 화면

- 3개 카드: 워크숍 · 심화 멘토링 · 겨울 심화캠프
- 학생 작품은 이 화면에 없음. 8절 "상시 검색" 참조
- 그 분야에 「일정」이 하나도 없는 프로그램 카드는 흐리게 하고 「준비중」 표시, 클릭 불가 (2026-10-07 차장님 요청 — 멘토링·캠프 자료가 아직 없음). 시트에 일정을 넣으면 코드 수정 없이 다시 열림. 로그인 직후 자료를 받기 전에는 판단할 수 없어 열어 두고, 자료가 도착하면 반영

## 5. 일정표 화면

프로그램마다 레이아웃이 다르다.

| 프로그램 | 형태 | 묶는 기준 |
|---|---|---|
| 워크숍 | 격자 (일자 × 시간대, 30분 줄. 실제 일정표처럼 수업 칸을 길이만큼 세로로 늘이고 같은 시간 수업은 좌우로 나눔 — 2026-10-08) | 일자 × 시간대 |
| 심화 멘토링 | 격자 (권역 × 회차) | 분야 × 권역 × 회차 |
| 겨울 심화캠프 | 카드 (일자별) | 일자 |

- 자료를 보유한 칸은 강조 표시("● 영상 N · 사진 N"). 워크숍 격자는 칸 테두리 없이 **둥근 카드 + 카드 사이 틈**으로 나누고, 원본 일정표처럼 **수업마다 옅은 색**을 칠한다 — 같은 수업은 날짜가 달라도 같은 색(괄호·끝의 A/B는 떼고 묶음: 특강(초등)=특강(중고등), 융합창작 A=B), 영상 없는 칸은 회색 카드에 흐린 글자. 칸 글자는 가운데 정렬 (2026-10-08, 시안 2개 중 사용자 선택. 금색 테두리로 구분하던 방식은 폐기)하고, 누르면 수업 자료 화면(6절)으로 이동한다. **자료가 없는 칸(점심·등록·개별 연습 등)은 흐리게 두고 누를 수 없다** (2026-10-08, 부실장님 피드백 "칸을 누르면 영상이 있으면 영상을 표출"). 그 전에는 "항상 클릭 가능"(2026-09-18)이었으나, 실제 일정표로 바꾸면서 점심·등록 칸이 생겨 눌러도 빈 화면인 칸이 많아짐
- 데이터는 `data` 응답의 `sessions` + `materials`를 세션ID로 대조해 보유 여부를 계산 (추가 요청 없음)

**재활용**: 기존 `index.html`의 `buildScheduleTable()` — 30분 슬롯 매트릭스 + sticky 헤더. 심화 멘토링 격자(권역×회차)는 기존 함수가 다루지 않는 새 구조라 별도 구현이 필요함.

**스크롤 (2026-10-08)**: 표 안의 세로 스크롤(높이 제한 68vh)을 없애고 사이트 스크롤 하나로만 본다 — 스크롤바가 두 개라 일정표가 한눈에 들어오지 않았음(사용자). 표가 화면보다 넓을 때(휴대폰)만 표를 옆으로 민다. 그래서 날짜 머리줄은 세로로 내릴 때 고정되지 않는다(표 안 스크롤일 때만 고정됐음). 시간 열은 옆으로 밀 때 계속 고정.

**같은 시간대 여러 수업 (2026-10-08 다시 변경)**: 10-07에는 「일정」이 녹화 단위라 동시 수업이 최대 12개(전통)여서, 30분 칸마다 시작하는 수업을 위아래로 나열했다. 10-08에 「일정」을 실제 일정표 칸으로 바꾸면서 동시 수업이 최대 2개(특강(중고등) | 전공실기(초등), 알렉산더 테크닉 A | 융합창작 B 등)가 되어, **실제 일정표처럼 칸을 길이만큼 늘이고(rowSpan) 그 날짜 열을 좌우로 나눈다(colSpan).** 겹치는 수업끼리 한 묶음으로 보고 세션ID 순번 순서(왼쪽부터 1, 2)로 줄을 배정하며, 겹치지 않는 수업은 열 전체를 쓴다. 칸 맨 위에 `14:00–16:00`처럼 시간을 적는다. 심화 멘토링은 같은 권역·회차에 수업이 여럿이면 한 칸에 `10.15 14:00–16:00`처럼 일자·시간을 붙여 나열한다(하나면 예전 칸 그대로). `docs/decisions.md` 9절 「실제 일정표로 교체」.

**심화 멘토링 격자 배치 (2026-09-17 결정)**: 권역을 열(가로), 회차를 행(세로)으로 둔다. 권역 수는 적고(보통 몇 군데) 회차는 계속 늘어나는 구조라 회차를 행으로 두는 쪽이 표가 세로로만 길어져 스크롤 대응이 쉽다.

**일정표 상단 (2026-09-18 결정)**: 뒤로가기 화살표 버튼 + "{분야} {프로그램} 일정표" 제목을, 해당 분야 대표 사진을 배경으로 깐 히어로 배너 위에 표시한다(분야 선택 화면의 타일 사진 재사용). "MUSIC · 워크숍" 같은 영문 라벨과 "프로그램 다시 선택" 텍스트 링크는 넣지 않는다. 워크숍·멘토링·캠프 3종 모두 동일하게 적용.

## 6. 수업 자료 화면 (목록·열람)

**2026-10-07 변경**: 일정표 칸(또는 검색의 "수업", 인물 상세의 "참여 클래스")을 누르면 목록 카드 화면을 거치지 않고 아래 구성이 바로 펼쳐진다. 주소는 그대로 `#/music/workshop/세션ID`.

- 위쪽: ← 버튼(들어온 곳으로 돌아감), 날짜·시간, 수업명, 강사·장소, 참여자 칩(「참여자」 탭에서 세션ID로 조회)
- 가운데: 재생·확대 칸. 들어오면 첫 영상을 띄우고(자동 재생은 하지 않음), 영상이 없으면 첫 사진을 띄움
- 오른쪽: 영상·사진 목록. 둘 다 있으면 **영상 · 사진 탭**, 한 종류뿐이면 탭 없이 「영상 목록 (N)」·「사진 목록 (N)」 제목만. 탭을 바꿔도 가운데 칸은 그대로라 영상을 틀어 둔 채 사진을 둘러볼 수 있고, 항목을 눌러야 가운데 칸이 바뀜
- 가운데 제목은 파일명 대신 **수업명**(「오프닝」, 영상이 여럿이면 「오프닝 · 영상 2」), 파일명은 제목 아래 작게. 오른쪽 목록은 「영상 1」「사진 3」 + 파일명 작게. 파일명은 원본 찾기표로 하드 원본을 찾는 열쇠라 지우지 않음 (2026-10-07). 「자료」에 소제목(반·악기 이름)이 있으면 그 이름 안에서 번호를 매겨 「전공실기 · 해금2 · 영상 1」, 목록은 「해금2 · 영상 1」(그 이름의 영상이 하나면 「해금2」) (2026-10-08). 인물 상세 모달은 여러 수업이 섞여 있어 파일명 그대로
- **현재 시각 링크 복사** (2026-10-07): 가운데에 영상이 떠 있으면 제목 오른쪽에 버튼. 누르면 Vimeo 플레이어에 현재 재생 시각을 물어(postMessage, 외부 라이브러리 없음) `#/music/workshop/세션ID?v=영상 순번&t=초` 주소를 복사하고 「01:15 시점 링크를 복사했습니다」 안내. 시각을 읽지 못하면 시각 없이 영상 링크만 복사. 받은 사람이 열면 로그인 후 그 수업 화면으로 이어지고(로그인 전 주소를 유지), 그 영상을 그 시각에 맞춰 띄움(`#t=초s`, 재생은 이용자가 누름 — 소리 있는 자동 재생은 브라우저가 막는 경우가 많음). 적용한 뒤 주소창은 `?v=…&t=…`를 뗀 수업 주소로 되돌림. 영상은 「자료」 탭의 그 수업 영상 순서로 가리키므로, 행 순서를 바꾸면 이전에 복사한 링크가 다른 영상을 가리킬 수 있음. 링크에는 토큰이 들어가지 않음
- 자료가 하나도 없으면 「영상 준비중」 빈 화면
- 사진묶음은 목록에 흐린 항목(「열람 방식 확인 중」)으로만 표시, 클릭 불가
- 폭이 좁은 화면(860px 이하)에서는 재생 칸 위, 목록 아래로 쌓음
- 다른 화면으로 옮기거나 로그아웃하면 플레이어를 지움(숨기기만 하면 재생 중인 소리가 계속 나므로)
- 한 시간대에 자료가 여러 건인 경우가 일반적(카메라 복수 운용, 녹화 분할, 사진 다수)이라 오른쪽 목록을 항상 보여 줌 (`docs/decisions.md` 2절)

## 7. 열람 화면

| 자료유형 | 방식 |
|---|---|
| 영상 · 작품(영상) | 화면 안 재생(Vimeo). 사이트 밖에서 열리면 도메인 제한이 무력해지므로 새 탭으로 열지 않음 |
| 사진 · 작품(이미지) | 확대 보기. `photo` 요청으로 축소본을 받아 표시 |
| 참여자 칩 | 클릭 시 인물 상세 화면으로 이동 |

**모달 구조 (2026-09-18 결정)**: 기존 `index.html`의 영상 모달(사이드바 목록 + 가운데 재생, 닫을 때 iframe 제거)을 그대로 재활용하되 사진에도 동일하게 적용한다. 영상 카드를 누르면 그 세션의 영상 전체 목록(사이드바) + 가운데 재생, 사진 카드를 누르면 사진 전체 목록(사이드바) + 가운데 확대. 사이드바에서 다른 항목을 누르면 모달을 닫지 않고 가운데 내용만 바뀐다.

**2026-10-07 이후**: 수업 자료 화면은 같은 열람기를 모달이 아니라 화면 안에 펼친다(6절). 모달은 인물 상세(여러 수업의 자료가 섞인 목록 카드)에서만 쓴다. 두 곳이 같은 코드(`site/js/view-materials.js`의 열람기)를 쓴다.

**금지**: 워터마크 표시, 검색엔진 노출(전 화면 `noindex` 또는 `robots.txt` 차단).

**영상 내려받기 (2026-11-03)**: 「내려받기」가 허용인 접근코드로 들어오면 영상 열람기(수업 자료 화면 · 인물 상세 창) 위 「현재 시각 링크 복사」 옆에 「내려받기」 단추가 보인다. 누르면 관문에서 화질 목록(원본 · 1080p · 720p … 와 크기)을 받아 펼치고, 고른 화질을 브라우저가 파일로 저장한다(화면은 그대로). 다른 영상으로 넘어가면 목록을 닫는다. 720px 이하에서는 단추 줄을 제목 아래로 내린다. 허용되지 않은 코드에는 단추가 없다(`docs/decisions.md` 9절).

## 8. 상시 검색

- 상단바에 항상 노출, 어느 단계에서도 검색 가능
- 대상: 분야 · 활동명 · 수업명 · 교강사 · 학생 · 장소
- 결과는 **사람 · 수업 · 작품**으로 구분해 표시 (한 번의 입력으로 전체를 조회하되 성격이 섞이지 않게 함)
  - **2026-10-08 변경**: "사람"은 「참여자」와 학생 작품의 학생명을 함께 본다. 출석부가 아직 없어 작품만 있는 학생을 작품 목록에서 눌렀을 때 인물 상세가 「인물을 찾을 수 없습니다」로 나오던 문제 때문(음악 학생 영상 24명). 학생 작품은 학생 이름으로만 찾으므로 별도 "작품" 목록 대신 "사람"(→ 인물 상세의 「학생 작품」)으로 이어진다. 인물 상세도 「참여자」에 없으면 학생 작품에서 찾고, 참여 클래스가 0개면 「등록된 참여 기록이 없습니다」를 표시. 출석부가 들어오면 같은 이름(또는 학생ID)으로 한 사람으로 묶인다
- 인물 상세: **참여 클래스**(세션 목록) + **학생 작품**(`materials`를 세션ID·학생ID로 대조). "함께 참여한 인물"은 넣지 않음 — 참여 클래스를 눌러 그 세션 자료 화면으로 들어가면 참여자 칩으로 이미 나오는 정보라 중복임 (2026-09-18 결정)
- 동명이인: `participants`·`materials`의 `studentId`가 서로 다르면 검색 결과를 목록으로 보여주고, 선택해야 인물 상세로 이동 (`docs/sheet-schema.md` 13절). `studentId`가 없는 학생(동명이인 없음, 즉 검색된 이름이 한 명으로 특정됨)은 검색 결과 화면을 거치지 않고 **바로 인물 상세로 이동**
- 성명 검색은 접근코드 인증자에게만 제공. 홍보 사이트에는 어떤 형태로도 제공하지 않음

검색은 `data` 응답으로 받은 `sessions` · `materials` · `participants`를 브라우저에서 필터링해 처리하며, 추가 관문 요청을 만들지 않는다.

**구현 메모 (2026-09-18, `site/js/view-search.js`·`view-person.js`)**
- 이름이 한 명으로 특정되면(`studentId`로 구분되는 동명이인이 없으면) 검색 결과 화면 없이 바로 인물 상세로 이동. 뒤로가기가 검색↔인물 상세 사이에서 튕기지 않도록 `history.replaceState`로 주소만 바꾸고 검색 화면은 히스토리에 남기지 않는다.
- 이름이 여럿과 겹치면(동명이인) "사람" 목록만 보여주고, 그 학생의 수업·작품이 다른 동명이인 것과 섞이지 않도록 "수업"·"작품" 섹션은 그 자리에서 보여주지 않는다 — 목록에서 선택해 인물 상세로 들어가야 확인 가능.
- 이름이 하나도 안 걸리면(장소·수업명·교강사 검색 등) 기존처럼 "수업"·"작품" 결과를 보여주되, 결과가 없는 섹션은 표시하지 않는다.
- 검색 결과의 "수업" 행은 그 세션의 자료 목록 화면으로, "작품" 행은 그 학생의 인물 상세로 이동.
- 인물 상세의 "참여 클래스 자료"·"학생 작품"은 영상/사진 탭 목록 카드 + 사이드바 재생 모달(`buildMaterialsSection`)을 쓴다(수업 자료 화면은 2026-10-07부터 열람기를 화면 안에 바로 펼침, 6절). 내용이 없으면 그 섹션 자체를 표시하지 않음(참여 클래스만 항상 표시).
