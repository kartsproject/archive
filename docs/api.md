# 관문 API 명세

> 관문 = Google Apps Script 웹앱. 열람 화면과 자료 관리 시트 사이에서 요청마다 권한을 확인한다.

---

## 1. 확정 사항

| 항목 | 규칙 |
|---|---|
| 응답 | JSON만, `{ ok, error, data }` 고정 |
| 요청 | auth(로그인) · ping(연장) · data(자료) · photo(사진) · photos(수업 사진 묶음) |
| 토큰 | 2시간, 사용 중 연장, 코드 `버전` 변경 시 전부 무효 |
| 실패 제한 | 기기별 5회 → 10분 잠금, 급증 시 운영진 메일 |
| 로그 | 모든 로그인·자료 요청 기록 |
| 영상 서비스 | 설정값으로 교체 가능 (기본 Vimeo) |

**보안 원칙** (`docs/decisions.md` 6절)

- 인증·토큰·공개여부·자료 허용 여부는 **모두 관문에서 매 요청 검증**한다.
- 공개여부가 `공개`인 자료만 내보낸다.
- 서명 키는 Script Properties에만 둔다. 토큰은 HMAC 서명하고 **요청 본문으로만** 전달한다(URL 금지).
- 관문은 HTML을 내보내지 않는다.
- 시트에 기록하는 값은 수식 주입을 막는다(`=` `+` `-` `@`로 시작하면 앞에 `'`).

---

## 2. 응답 형식

모든 응답은 아래 형태를 벗어나지 않는다.

```json
{ "ok": true,  "error": null,        "data": { } }
{ "ok": false, "error": "코드",       "data": null }
```

| 필드 | 형 | 설명 |
|---|---|---|
| `ok` | boolean | 성공 여부 |
| `error` | string \| null | 실패 시 오류 코드. 성공 시 `null` |
| `data` | object \| null | 성공 시 결과. 실패 시 `null` |

이 형식을 고정하는 이유는 나중에 관문을 다른 백엔드로 교체해도 화면 코드를 고치지 않기 위함이다.

---

## 3. 요청별 명세

| 요청 | 용도 |
|---|---|
| `auth` | 접근코드·이름으로 로그인하고 토큰을 받는다 |
| `ping` | 사용 중 토큰 유효시간을 연장한다 |
| `data` | 공개 자료를 받는다 |
| `photo` | 대표 사진 축소본을 받는다 |
| `photos` | 수업 하나의 대표 사진을 한 번에 받는다 (미리 받기용) |

모든 요청은 POST 본문에 `action` 필드로 종류를 담아 보낸다(토큰을 URL에 넣지 않기 위함, 6절 참조).

> 관리자 페이지 요청(`adminAuth` · `adminPing` · `adminCodes` 등, 2026-10-29 추가)은 `docs/admin.md` 8·10절에 따로 적는다.

### 3-1. auth

로그인. 접근코드·이름·기기ID로 토큰을 받는다.

**요청**

| 필드 | 설명 |
|---|---|
| `action` | `"auth"` |
| `requestId` | 요청마다 새로 만드는 값. 화면이 응답 지연 시 같은 요청을 한 번 더 보내므로(예비 요청, `docs/decisions.md` 9절), 관문은 같은 `requestId`면 먼저 만든 응답을 그대로 돌려준다. 없으면 매번 새로 처리한다 |
| `code` | 접근코드 (`KA-MUSIC-7Q4F` 형식) |
| `name` | 입력한 이름. 로그·기록용이며 별도 명단과 대조하지 않음 |
| `deviceId` | `localStorage`의 기기ID |

**응답 `data`**

| 필드 | 설명 |
|---|---|
| `token` | 서명된 토큰 |
| `expiresAt` | 만료 시각 (발급 시점 + 2시간) |
| `firstView` | 「접근코드」 탭의 "첫 화면" 값 (진입 시 이동할 분야·화면) |

**검증 순서**: 코드 존재 → 상태 "사용" → 사용기한 이내 → 기기별 실패 횟수(6절) → 통과 시 토큰 발급, 「로그」 기록.

### 3-2. ping

토큰 유효시간을 연장한다.

**요청**

| 필드 | 설명 |
|---|---|
| `action` | `"ping"` |
| `token` | 현재 토큰 |

**응답 `data`**

| 필드 | 설명 |
|---|---|
| `token` | 연장된 새 토큰. 화면은 기존 토큰을 이 값으로 교체해 `sessionStorage`에 다시 저장한다 |
| `expiresAt` | 연장된 만료 시각 |

> 토큰은 만료 시각을 서명해 넣는 자체 완결형(stateless)이라 서버에 세션을 따로 저장하지 않는다. 연장할 때마다 새 토큰을 발급하는 이유다.

### 3-3. data

공개 자료를 **한 번에** 받는다. 인증 직후 1회 호출하고, 이후 화면 이동·검색은 이 응답을 브라우저에 캐시해 처리한다(요청 수를 줄여 실행 한도를 아끼기 위함, `docs/decisions.md` 2절).

**요청**

| 필드 | 설명 |
|---|---|
| `action` | `"data"` |
| `token` | 현재 토큰 |

**응답 `data`**

| 필드 | 내용 |
|---|---|
| `sessions` | 세 프로그램 시트의 「일정」 탭 전체를 합친 것 |
| `materials` | 세 프로그램 시트의 「자료」 탭 중 **공개여부 = 공개**만 합친 것 |
| `participants` | 세 프로그램 시트의 「참여자」 탭 전체를 합친 것 — 성명 검색용 |
| `settings` | 공통 시트 「설정」 탭 값 (영상 서비스 등) |

> 토큰이 유효한 이용자는 전체 열람 대상이므로(`docs/decisions.md` 8절) 분야별로 따로 나누어 내려주지 않는다.
>
> 시트가 프로그램별로 나뉘어도(`docs/sheet-schema.md` 2절) **응답 모양은 그대로다.** 관문이 세 시트를 읽어 한 배열로 합치므로 화면 코드는 시트 구성을 알 필요가 없다.

**필드명**: 시트 열(한글)을 화면이 쓰는 영어 camelCase로 옮긴다 (`ok`·`error`·`data`·`token`·`expiresAt` 등 최상위 필드와 통일).

| `sessions[]` | 시트 열 |
|---|---|
| `sessionId` | 세션ID |
| `program` | 시트 열이 아님 — 관문이 **읽은 시트**에 따라 채운다 (워크숍 · 심화 멘토링 · 겨울 심화캠프) |
| `discipline` | 분야 |
| `date` | 일자 |
| `startTime` | 시작시각 |
| `endTime` | 종료시각 |
| `region` | 권역 |
| `round` | 회차 |
| `className` | 수업명 |
| `instructor` | 강사명 |
| `note` | 비고 — **확인 필요**: "장소" 정식 열이 없어 임시로 여기 담음 (`docs/sheet-schema.md` 3-2) |

| `materials[]` | 시트 열 |
|---|---|
| `sessionId` | 세션ID |
| `type` | 자료유형 |
| `fileName` | 파일명 |
| `link` | 링크 |
| `spec` | 규격 |
| `studentName` | 학생명 |
| `studentId` | 학생ID — 작품(영상)·작품(이미지)이고 동명이인일 때만 값이 있음. 동명이인 구분용(`docs/sheet-schema.md` 13절) |
| `discipline` | 분야 |
| `subtitle` | 소제목 — 한 수업 칸 안 영상의 반·악기 이름(「해금2」). 열이 없거나 비면 빈 값 (2026-10-08 추가) |

| `participants[]` | 시트 열 |
|---|---|
| `name` | 성명 |
| `studentId` | 학생ID — 동명이인일 때만 값이 있음. 동명이인 구분용(`docs/sheet-schema.md` 13절) |
| `sessionId` | 세션ID |

`settings`는 `{ 항목: 값 }` 형태의 객체다 (예: `{ "영상서비스": "Vimeo" }`).

### 3-4. photo

대표 사진 축소본을 받는다. 응답이 JSON만이므로(1절) 이미지는 base64로 담는다.

**요청**

| 필드 | 설명 |
|---|---|
| `action` | `"photo"` |
| `token` | 현재 토큰 |
| `fileId` | 「자료」 탭의 링크(Drive 파일 ID) |

**응답 `data`**

| 필드 | 설명 |
|---|---|
| `base64` | 이미지 데이터 |
| `mimeType` | 예: `image/jpeg` |

> 요청 시점에도 해당 자료의 공개여부를 다시 확인한다(요청마다 검증, `docs/decisions.md` 6절).
> 학생 작품은 세션ID가 없어 어느 시트의 행인지 알 수 없으므로, 세 프로그램 시트의 「자료」를 모두 찾아본다.

### 3-5. photos

수업(세션) 하나의 대표 사진을 한 번에 받는다(2026-09-30 추가). 사진은 요청 한 번의 왕복 비용(약 3초)이 크기보다 커서,
자료 페이지에 들어가면 화면이 이 요청을 뒤에서 한 번 보내 사진을 미리 받아 둔다. 클릭 시 한 장씩 받는 `photo`는 그대로 쓴다.

**요청**

| 필드 | 설명 |
|---|---|
| `action` | `"photos"` |
| `token` | 현재 토큰 |
| `sessionId` | 세션ID |

**응답 `data`**

| 필드 | 설명 |
|---|---|
| `photos` | `[{ fileId, base64, mimeType }]` — 묶음에 담은 사진 |
| `skipped` | `[fileId]` — 크기 때문에 뺀 사진. 화면은 클릭할 때 `photo`로 받는다 |

**담는 규칙**

| 규칙 | 값 | 이유 |
|---|---|---|
| 대상 | 그 세션의 자료유형 `사진` 중 공개여부 `공개`인 행 (「자료」 탭 순서) | 사진묶음은 열람 방식 미정, 작품은 세션ID가 없음 |
| 사진 목록 결정 | **관문이** 시트에서 찾는다. 화면은 세션ID만 보낸다 | 화면을 믿지 않는다 (1절 보안 원칙) |
| 한 장 상한 | 1MB 이상이면 뺀다 | 원본 한 장이 묶음 전체를 늦추지 않게 함. 크기는 파일 내용을 읽기 전에 확인한다 |
| 합계 상한 | 4MB를 넘기게 되는 사진부터 나머지 전부를 뺀다 | 응답이 커지지 않게 함. 뺀 사진은 드라이브를 열지 않는다 |
| 열 수 없는 파일 | `skipped`에 넣는다 | 클릭 시 `photo`가 `NOT_FOUND`로 알려 준다 |

> 공개 사진이 없는 세션이면 `photos`·`skipped` 모두 빈 배열이다(오류 아님). 화면은 공개 사진이 없는 세션에는 이 요청을 보내지 않는다.
> 화면은 이 요청에 **예비 요청(3초 뒤 재전송)을 쓰지 않는다.** 뒤에서 받는 요청이라 서두를 필요가 없고, 관문 부하가 두 배가 되는 것을 막는다.

## 4. 오류 코드

| 코드 | 상황 |
|---|---|
| `AUTH_INVALID` | 접근코드가 존재하지 않거나 상태가 "사용"이 아님 |
| `AUTH_EXPIRED` | 접근코드 사용기한이 지남 |
| `AUTH_LOCKED` | 기기별 실패 5회로 10분 잠금 (6절) |
| `TOKEN_INVALID` | 토큰이 없거나 서명이 맞지 않음 |
| `TOKEN_EXPIRED` | 토큰 만료(2시간 경과 또는 코드 버전 변경으로 일괄 무효화) |
| `NOT_FOUND` | 요청한 자료가 없거나 공개여부가 "공개"가 아님 |
| `SERVER_ERROR` | 그 외 관문 내부 오류 |

## 5. 토큰

| 항목 | 규칙 | 이유 |
|---|---|---|
| 유효시간 | 서버 기준 2시간 | 방치된 세션은 만료시키되 열람 중에는 끊기지 않게 함 |
| 연장 | 사용 중 자동 연장 (`ping`) | 위와 같음 |
| 서명 | HMAC. 서명 키는 Script Properties에만 보관 | 주소·코드에서 키가 드러나지 않게 함 |
| 전달 | 요청 본문으로만. URL에 넣지 않는다 | 주소 기록·로그에 토큰이 남지 않게 함 |
| 보관 위치 | 화면 쪽 `sessionStorage` | 탭·브라우저를 닫으면 해제됨 |
| 일괄 무효화 | 시트 「접근코드」 탭의 **버전** 값을 올리면 해당 코드의 모든 접속이 즉시 해제됨 | 코드 유출 시 즉시 차단 수단이 필요함 |
| 장기 토큰 | 사용하지 않음 | 공용 PC에서 세션이 오래 남지 않게 함 |

## 6. 실패 제한

| 항목 | 규칙 |
|---|---|
| 기기별 | 5회 실패 시 10분 잠금 |
| 코드별 | 코드 앞부분(배포 단위) 기준 누적 제한 |
| 알림 | 실패가 급증하면 운영진에게 메일 |
| 기기ID | `localStorage`의 무작위 값. **인증 수단이 아니며** 실패 제한·로그 구분용으로만 쓴다 |

**구현 메모** — 임계치는 시트 「설정」 탭(항목-값)에서 읽고, 값이 없으면 기본값을 쓴다. 코드 수정 없이 시트에서 조정 가능.

| 설정 항목 | 기본값 | 비고 |
|---|---|---|
| 기기별 실패 잠금 기준 | 5 | |
| 기기별 잠금 시간(분) | 10 | |
| 코드별 실패 급증 기준 | 20 | **확인 필요** — "급증"의 정확한 기준이 정해지지 않아 임시값 |
| 코드별 실패 급증 판단 시간(분) | 5 | **확인 필요** — 판단 시간(창)도 정해지지 않아 임시값 |
| 운영진 알림 메일 | (비움) | **확인 필요** — 비어있으면 급증해도 메일을 보내지 않음 |

---

## 7. 로그

모든 **로그인**과 **자료 요청**을 시트 「로그」 탭에 기록한다.

기록 항목: 일시 · 결과 · 코드 · 이름 · 기기ID · 요청 · 대상 자료

열 구성 상세는 `docs/sheet-schema.md` 참조.

---

## 8. 영상 서비스 설정

영상 서비스는 시트 「설정」 탭의 값으로 선택한다. 기본값은 Vimeo이며, 관문과 화면은 서비스 이름을 직접 하드코딩하지 않는다.
