## 0. 먼저 알아 둘 것

### 사이트가 움직이는 방식

```
방문자 ─▶ GitHub Pages(화면) ─▶ 관문(Apps Script 웹앱) ─▶ 구글 시트 · 드라이브
                                     ▲
           GitHub Actions 「Gateway」가 저장소의 apps-script/ 코드를 관문에 올림(자동 배포)
```

| 말 | 뜻 |
|---|---|
| **관문** | 화면이 부르는 Google Apps Script 프로그램. 시트에 붙어 있고(시트 메뉴 「확장 프로그램 › Apps Script」), 「웹앱」으로 배포하면 `https://script.google.com/macros/s/…/exec` 주소가 생깁니다 |
| **스크립트 속성** | 관문만 읽는 비밀 설정값(토큰 · 시트 ID 등). Apps Script 편집기 ⚙ 프로젝트 설정 맨 아래에 있습니다 |
| **clasp** | 구글이 만든 Apps Script 도구. PC에서 한 번 로그인해 「출입증」 파일(`.clasprc.json`)을 만드는 데만 씁니다 |
| **GitHub Secrets** | 저장소에 넣어 두는 비밀값. 자동 배포가 이 값으로 새 계정의 관문에 코드를 올립니다 |

### 준비물

## 1단계. 공통 — clasp 출입증(`CLASPRC_JSON`) 만들기

두 사이트 모두 같은 출입증을 씁니다. **한 번만** 하면 됩니다.

### 1-1. Apps Script API 켜기
1. 새 계정으로 https://script.google.com/home/usersettings 에 들어갑니다.
2. **Google Apps Script API**를 **사용**으로 바꿉니다.

### 1-2. Node.js 설치
1. https://nodejs.org 에서 **LTS** 버전을 받아 설치합니다. 옵션은 기본값 그대로 두고 「다음」만 누르면 됩니다.
2. 터미널을 엽니다.
   - Windows: 시작 메뉴에서 **PowerShell**
   - Mac: **터미널**
3. `node -v`를 입력하고 Enter를 누릅니다. `v22.…`처럼 숫자가 나오면 됩니다.

### 1-3. clasp 설치 · 로그인
터미널에 한 줄씩 입력합니다.
```
npm install -g @google/clasp@3.4.1
clasp login
```
- Mac에서 권한 오류가 나면 첫 줄 앞에 `sudo `를 붙입니다(PC 암호 입력).
- Windows PowerShell에서 「이 시스템에서 스크립트를 실행할 수 없으므로 … npm.ps1」 오류가 나면 `npm` · `clasp` 대신 **`npm.cmd` · `clasp.cmd`**로 입력합니다(예: `npm.cmd install -g @google/clasp@3.4.1`, `clasp.cmd login`). PC 보안 설정은 바꾸지 않아도 됩니다.
- 브라우저가 열리면 **새 구글 계정**을 고르고 「허용」을 누릅니다. 「Logged in」 같은 문구가 나오면 끝입니다.
- 이미 예전 계정으로 로그인한 적이 있으면 먼저 `clasp logout`을 실행한 뒤 `clasp login`을 합니다.

### 1-4. 출입증 내용 복사 (화면에 띄우지 않고 클립보드로)
- Windows: `Get-Content $HOME\.clasprc.json -Raw | Set-Clipboard`
- Mac: `cat ~/.clasprc.json | pbcopy`

복사한 내용은 **비밀번호와 같습니다.** 채팅 · 메일 · 문서에 붙이지 말고 GitHub Secrets 칸에만 붙여 넣으세요(2-3, 3-3). 클립보드가 지워지면 이 명령을 다시 실행하면 됩니다.

## 2단계. 홍보 사이트 (`kartsproject/home`)

### 2-1. 예전 계정에서 공유하기 (예전 계정으로 로그인)
1. 구글 드라이브에서 **홍보 사이트 게시글 시트**를 찾습니다. 「공지 · 갤러리 · 언론홍보 · 표지 · 첨부 · 접근코드」 탭이 있는 시트입니다.
2. 이 시트를 「공유」 → 새 계정 이메일 → **뷰어**로 공유합니다.
3. 내 드라이브의 **「K예술영재 홍보 사이트 첨부」** 폴더도 새 계정에 **뷰어**로 공유합니다. 동영상 조각처럼 공유돼 있지 않은 파일까지 옮기기 위해서입니다.

### 2-2. 새 계정에서 시트 사본 만들기 (새 계정으로 로그인)
1. 드라이브 「공유 문서함」에서 2-1의 시트를 엽니다.
2. **파일 › 사본 만들기**를 누릅니다. 이름은 예를 들어 `K예술영재 홍보 사이트 게시글`로 하고, 위치는 「내 드라이브」로 둡니다.
   - 사본에는 글 · 첨부 목록 · 접근코드가 그대로 들어가고, 시트에 붙은 관문 코드(Apps Script)도 같이 복사됩니다.
3. **사본**에서 **확장 프로그램 › Apps Script**를 엽니다. 편집기 왼쪽 ⚙ **프로젝트 설정** → 「스크립트 ID」를 **복사**해 둡니다.
4. 사본의 주소(`https://docs.google.com/spreadsheets/d/<여기>/edit`)도 기록해 둡니다. 실제 값은 저장소 파일에 쓰지 말고 `docs/private/`(PC)에만 적습니다.

### 2-3. GitHub 비밀값 넣기
1. https://github.com/kartsproject/home → **Settings** → 왼쪽 **Secrets and variables › Actions**로 갑니다.
2. **New repository secret**으로 두 개를 등록합니다. 이미 있으면 연필(Update)을 눌러 새 값으로 바꿉니다.

| Name | 값 |
|---|---|
| `CLASPRC_JSON` | 1-4에서 복사한 내용 전체 (`{`로 시작해 `}`로 끝남) |
| `GAS_SCRIPT_ID` | 2-2 ③의 스크립트 ID |

### 2-4. 최신 관문 코드 올리기
1. 저장소 **Actions** 탭 → 왼쪽 **Gateway** → 오른쪽 **Run workflow** → `main` → **Run workflow**를 누릅니다.
2. 1~2분 뒤 초록 체크가 생기면 됩니다. 노란 경고 「관문 배포가 없음 — 코드는 올렸고 배포는 건너뜀」이 뜨는 것이 **정상**입니다. 배포는 2-8에서 만듭니다.
3. Apps Script 편집기를 새로고침해 왼쪽 파일 목록에 `Migrate.gs` · `CheckSetup.gs` · `Photos.gs`가 보이면 코드가 올라간 것입니다.

### 2-5. 기본 설정 실행 (`setup`)
1. 편집기 위쪽 함수 고르는 칸에서 **`setup`**을 고르고 **▶ 실행**을 누릅니다.
2. 처음에는 권한 승인 창이 뜹니다.
   - 「권한 검토」 → 새 계정을 선택합니다.
   - 「Google에서 확인하지 않은 앱」이 나오면 **고급 → (프로젝트 이름)(으)로 이동(안전하지 않음)** → **허용**을 누릅니다. 직접 만든 스크립트라 뜨는 화면입니다.
3. 아래 실행 기록에 「완료」가 나오면 됩니다. 이때 서명 키와 새 첨부 폴더(내 드라이브 › K예술영재 홍보 사이트 첨부)가 만들어지고, 발행 위치가 `main`으로 정해집니다.

### 2-6. GitHub 토큰 넣기 (`GITHUB_TOKEN`)
관문이 공개 글 파일(`data/posts.json`)을 저장소에 올릴 때 쓰는 열쇠입니다.

1. GitHub 오른쪽 위 프로필 → **Settings** → 맨 아래 **Developer settings** → **Personal access tokens › Fine-grained tokens** → **Generate new token**을 누릅니다.
2. 아래처럼 채웁니다.

| 항목 | 값 |
|---|---|
| Token name | `kartsproject-home-gateway` |
| Resource owner | **kartsproject** |
| Expiration | 사업 종료 이후 날짜(예: 2027-03-31). **만료일을 달력에 적어 둘 것** — 지나면 사이트 반영이 멈춥니다 |
| Repository access | Only select repositories → `home`, `home-media` |
| Permissions › Repository permissions | **Contents: Read and write** (나머지는 그대로) |

3. **Generate token**을 누르고 나온 `github_pat_…`를 복사합니다. 이 화면을 닫으면 다시 볼 수 없습니다. 조직 설정에 따라 kartsproject 관리자의 승인이 필요할 수 있습니다.
4. Apps Script 편집기 ⚙ **프로젝트 설정** → 맨 아래 **스크립트 속성** → **스크립트 속성 추가** → 속성 `GITHUB_TOKEN`, 값은 위 토큰 → **스크립트 속성 저장**을 누릅니다.

### 2-7. 첨부 옮기기 (`moveAttachments`)
예전 계정 드라이브의 사진 · 첨부파일을 새 계정 드라이브로 복사하고, 시트의 파일 번호를 새 것으로 바꿉니다. 그다음 사이트에 반영합니다.

1. 함수 칸에서 **`moveAttachments`** → **▶ 실행**을 누릅니다.
2. 실행 기록을 확인합니다.
   - 「✅ 끝 — 사이트에 반영했습니다」 → 완료
   - 「⏸ 시간이 모자라 멈췄습니다」 → 한 번 더 실행하면 이어서 합니다.
   - 「❌ …」 → 2-1 ③의 폴더 공유를 확인한 뒤 다시 실행합니다.
3. 메인 표지(분야별 큰 사진)는 옮기지 않습니다. 표지는 실사진(preview4와 같은 사진)이 기본으로 나오게 했습니다.
4. 예전 계정의 원본 파일은 그대로 둡니다. 5단계에서 정리합니다.

### 2-8. 웹앱 배포 만들기 (처음 한 번)
1. 편집기 오른쪽 위 **배포 › 새 배포** → 톱니 「유형 선택」 → **웹 앱**을 고릅니다.
2. 설명은 `홍보 사이트 관문`으로 하고 아래처럼 정합니다.
   - 실행 사용자: **나(새 계정)**
   - 액세스 권한: **모든 사용자**
3. **배포**를 누르고 나온 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다. 4단계에서 씁니다.
4. 앞으로 코드가 바뀌면 자동 배포가 **이 배포를 새 버전으로** 바꿉니다. 주소는 그대로이니 새 배포를 또 만들지 마세요.

### 2-9. 점검 (`checkSetup`)
함수 칸에서 **`checkSetup`** → **▶ 실행**을 누릅니다. 줄마다 ✅ / ❌ 와 고칠 방법이 나옵니다. ❌가 없으면 홍보 사이트의 구글 쪽은 끝입니다. 웹앱 주소 줄은 4단계에서 확인합니다.

> **접근코드**: 사본에 예전 코드가 그대로 들어 있습니다. 이번에 바꾸려면 「접근코드」 탭에서 코드를 고치세요. 따로 배포할 필요 없이 바로 적용됩니다.

## 3단계. 아카이빙 사이트 (`kartsproject/archive`)

예전에는 시트 파일이 4개였습니다. 관문이 붙은 **공통 시트**(학생 · 접근코드 · 설정 · 로그)와 **프로그램 시트 3개**(워크숍 · 심화 멘토링 · 겨울 심화캠프 — 각각 일정 · 자료 · 출석부 · 참여자)입니다.
이번에 **파일 하나로 합칩니다**(2026-11-04 결정). 공통 시트의 사본을 만들고, 프로그램 시트 3개는 그 사본 안으로 탭째 가져옵니다.

```
합친 뒤 탭: 읽어보기 · 학생 · 접근코드 · 설정 · 로그 · 관리기록
          워크숍_일정 · 워크숍_자료 · 워크숍_출석부 · 워크숍_참여자   (파란 탭)
          멘토링_일정 · 멘토링_자료 · 멘토링_출석부 · 멘토링_참여자   (보라 탭)
          캠프_일정 · 캠프_자료 · 캠프_출석부 · 캠프_참여자           (주황 탭)
```

입력 방법은 같습니다. 예전에 「워크숍 시트의 자료 탭」에 넣던 것을 이제 「워크숍_자료 탭」에 넣으면 됩니다. 시트 메뉴 「K예술영재 아카이브」(세션ID 생성 · 출석부 변환 · 영상 매칭 · 점검)도 그대로입니다.

### 3-1. 예전 계정에서 공유하기 (예전 계정으로 로그인)
1. 시트 **4개**(공통 1 + 프로그램 3)를 새 계정에 **뷰어**로 공유합니다.
2. **사진이 들어 있는 드라이브 폴더**도 새 계정이 볼 수 있어야 합니다. 「자료」 탭의 사진 · 작품(이미지)은 드라이브 파일 번호로 연결돼 있고, 관문(새 계정)이 그 파일을 읽어 화면에 보냅니다. 사진 폴더 위치는 확인이 필요합니다. 3-7 점검이 열리지 않는 사진 수를 알려 줍니다.

### 3-2. 새 계정에서 공통 시트 사본 만들기
1. 드라이브 「공유 문서함」에서 **공통 시트**(학생 · 접근코드 · 설정 · 로그 탭이 있는 것)를 열고 **파일 › 사본 만들기**를 합니다(내 드라이브). 이름은 예를 들어 `K예술영재 아카이브 시트`로 합니다.
   - **프로그램 시트 3개는 사본을 만들지 않습니다.** 3-6에서 함수가 탭을 가져옵니다.
2. 사본에서 **확장 프로그램 › Apps Script** → ⚙ 프로젝트 설정 → **스크립트 ID**를 복사합니다.
3. 프로그램 시트 3개는 「공유 문서함」에서 하나씩 열어 **주소창의 주소**를 메모장에 복사해 둡니다. 3-5에서 씁니다.

### 3-3. GitHub 비밀값 넣기
https://github.com/kartsproject/archive → **Settings › Secrets and variables › Actions**에서 아래 두 값을 넣습니다.

| Name | 값 |
|---|---|
| `CLASPRC_JSON` | 1-4와 **같은 값** |
| `GAS_SCRIPT_ID` | 3-2 ②의 스크립트 ID (홍보 사이트와 **다른 값**) |

### 3-4. 최신 관문 코드 올리기
2-4와 같습니다. archive 저장소 **Actions › Gateway › Run workflow**를 누릅니다. 노란 경고는 정상입니다.
편집기를 새로고침해 파일 목록에 `Import.gs` · `CheckSetup.gs`가 보이면 됩니다.

### 3-5. 스크립트 속성 넣기
Apps Script 편집기 ⚙ **프로젝트 설정 › 스크립트 속성**에 아래 값을 넣습니다.

| 속성 | 값 |
|---|---|
| `OLD_WORKSHOP_SHEET` | 예전 **워크숍** 시트 주소 (3-2 ③, 주소 통째로 붙여도 됨) |
| `OLD_MENTORING_SHEET` | 예전 **심화 멘토링** 시트 주소 |
| `OLD_CAMP_SHEET` | 예전 **겨울 심화캠프** 시트 주소 |
| `VIMEO_TOKEN` | Vimeo 토큰. 아래 둘 중 하나 |

- `OLD_…` 세 개는 가져올 때만 쓰고, 끝나면 지웁니다.
- 예전 공통 시트 사본에 `SHEET_ID_…` 속성이 보이면 지워도 됩니다(합친 뒤에는 쓰지 않음).
- 사본에 따라 스크립트 속성이 처음부터 비어 있을 수 있는데, 정상입니다.

**Vimeo 토큰** — Vimeo 계정은 그대로이니 둘 중 편한 방법을 쓰면 됩니다.
- **(가) 예전 값 쓰기**: 예전 계정으로 예전 공통 시트의 Apps Script → ⚙ 프로젝트 설정 → 스크립트 속성의 `VIMEO_TOKEN` 값을 복사합니다.
- **(나) 새로 발급**: https://developer.vimeo.com/apps → 앱 선택 → **Generate an access token** → Authenticated(you)를 고르고, 권한(scope)은 **Public · Private · Edit · Upload · Video Files**를 모두 체크합니다. Video Files가 없으면 영상 내려받기가 안 됩니다.

### 3-6. 함수 실행 (위에서부터 차례로)
함수 칸에서 고르고 ▶를 누릅니다. 첫 실행 때 2-5와 같은 권한 승인 창이 뜹니다.

| 순서 | 함수 | 하는 일 |
|---|---|---|
| 1 | `setupTokenSecret` | 새 서명 키 만들기 |
| 2 | `importProgramSheets` | 예전 프로그램 시트 3개의 일정 · 자료 · 출석부 · 참여자 탭을 이 시트로 복사해 `워크숍_일정` 등 12개 탭으로 붙임. 실행 기록에 탭마다 「가져옴 (n줄)」, 끝에 「✅ 끝」이 나와야 함. 여러 번 실행해도 이미 있는 탭은 건드리지 않음 |
| 3 | `setupAdminSheets` | 관리자 페이지용 열 · 탭 확인(이미 있으면 그대로) |
| 4 | `installTriggers` | 시트 편집 감지 + 1분마다 로그 기록 장치 설치 |
| 5 | `checkVimeoConnection` | Vimeo 연결 확인(실행 기록에 「연결 성공」) |

시트로 돌아가서 탭 12개가 색깔별로 붙어 있고, 예를 들어 `워크숍_일정`에 일정이 들어 있는지 눈으로 확인합니다. 확인이 끝나면 3-5의 `OLD_…` 속성 세 개를 지웁니다.

### 3-7. 웹앱 배포 만들기 · 점검
1. 2-8과 같은 방법으로 **새 배포 › 웹 앱**을 만듭니다. 실행 사용자는 **나**, 액세스는 **모든 사용자**입니다. 나온 **웹 앱 URL**을 복사해 둡니다.
2. **`checkSetup`** → ▶를 실행합니다. ❌ 줄을 안내대로 고칩니다. 사진 줄이 ❌이면 3-1 ②의 폴더 공유가 필요합니다.

## 4단계. 화면에 새 관문 주소 넣기

화면 코드에 관문 주소가 한 줄 적혀 있어 새 주소로 바꿔야 합니다. 둘 중 하나를 고릅니다.

- **(가) Claude에게 맡기기**: 2-8 · 3-7에서 복사한 두 주소를 「홍보: … / 아카이빙: …」처럼 보내 주세요. 바꿔서 반영합니다. 웹앱 주소는 화면 코드에 원래 공개되는 값이라 채팅으로 보내도 됩니다.
- **(나) 직접 고치기 (GitHub 웹)**:
  - 홍보: `kartsproject/home` → `assets/js/admin.js` → 연필(✎) → 9번째 줄 `var GATEWAY = '…';`의 따옴표 안을 새 주소로 바꿉니다 → **Commit changes**(main)를 누릅니다.
  - 아카이빙: `kartsproject/archive` → `site/js/api.js` → 7번째 줄 `const GATEWAY_URL = '…';` → 같은 방법으로 바꿉니다.

반영되고 1~2분 뒤부터 두 관리자 페이지와 아카이빙 열람 화면이 새 관문을 씁니다. 이 뒤로는 `apps-script/`가 바뀌어 main에 올라가면 자동 배포가 **이 배포를 새 버전으로** 바꿉니다.

## 5단계. 확인 · 예전 계정 정리

### 확인
- [ ] 홍보 관리자 페이지 `https://kartsproject.github.io/home/admin.html`에 로그인 → 공지 · 갤러리 목록이 보이고, 「사이트 사진」 탭에 카드 30개가 보이는지
- [ ] 아무 공지나 열어 [저장] → 「저장했습니다」 → 1~2분 뒤 사이트에 반영되는지
- [ ] 홍보 사이트 메인 표지 · 사진이 실사진(preview4와 같은 사진)으로 보이는지
- [ ] 아카이빙 `https://kartsproject.github.io/archive/`에 접근코드로 로그인 → 워크숍 일정표 · 영상 · 사진이 열리는지, 아카이빙 관리자 페이지 「영상 관리」에서 일정표가 보이는지
- [ ] 두 편집기에서 `checkSetup`을 한 번 더 실행해 ❌가 없는지

### 예전 계정 정리 (확인이 끝난 뒤)
1. 예전 시트들의 Apps Script → **배포 › 배포 관리** → 예전 웹앱 배포를 **보관처리**합니다. 예전 주소가 더는 동작하지 않게 됩니다.
2. 예전 계정의 「K예술영재 홍보 사이트 첨부」 폴더는 옮긴 사진이 사이트에서 잘 보이는 것을 확인한 뒤 지웁니다. 학생 사진이 들어 있으니 오래 두지 않는 편이 좋습니다.
3. 예전 시트(아카이빙 4개 · 홍보 1개)는 원본 보관용으로 두거나 지웁니다(사업 담당자와 정할 것). 예전 시트를 고쳐도 새 사이트에는 반영되지 않습니다.
4. 홍보 사이트의 예전 GitHub 토큰이 있으면 GitHub › Settings › Developer settings에서 **삭제**합니다.

## 문제가 생기면

| 증상 | 원인 · 해결 |
|---|---|
| Actions 「Gateway」가 빨간 X, `User has not enabled the Apps Script API` | 1-1을 안 함 → 켜고 다시 실행 |
| 「Gateway」 회색(건너뜀) · 「비밀값 확인」만 초록 | Secrets 이름이 틀림 → `CLASPRC_JSON` · `GAS_SCRIPT_ID` 철자 확인 |
| 「Gateway」 빨간 X, `invalid_grant` · 로그인 오류 | 출입증이 만료 · 취소됨 → PC에서 `clasp logout` → `clasp login` → 1-4 → Secrets 새 값으로 |
| 관리자 페이지 「사이트 반영에 실패」 | `GITHUB_TOKEN` 만료 · 권한 부족 → `checkSetup`의 GitHub 줄 확인, 2-6 다시 |
| 관리자 페이지 로그인이 안 됨 | 4단계 주소가 틀림(끝이 `/exec`인지), 또는 접근코드 「상태」가 「정지」 |
| 아카이빙 사진만 안 보임 | 새 계정이 사진 파일을 못 읽음 → 3-1 ② 공유, `checkSetup` 사진 줄 |

막히는 화면은 캡처해서 Claude에게 보내 주세요.
