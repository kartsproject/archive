> 기존 문서(`admin.md`·`decisions.md`·`api.md`)에는 브랜치를 합칠 때 원래 폴더 세션이 반영한다.

## 1. 확인 필요 ① 결과 — 브라우저에서 Vimeo로 직접 업로드: **가능** (2026-10-29)

| 확인 | 결과 |
|---|---|
| 업로드 주소 | `https://global.upload.vimeo.com/tus/uploads/{ID}?token=…` (기존 업로드 440건 모두 이 주소) |
| 사전 요청(OPTIONS) | `204`, `Access-Control-Allow-Origin: *` · `Allow-Headers: *` · `Allow-Methods`에 HEAD·PATCH 포함. 출처가 `kartsproject.github.io`든 `localhost`든 같다(2026-10-30 저장소 이전 뒤 새 주소로 다시 확인) |
| HEAD | `200`, `Upload-Offset` · `Upload-Length`를 주고 `Access-Control-Expose-Headers: *` → 화면 코드가 이어 올릴 위치를 읽을 수 있다 |
| 실제 브라우저 | 시험 페이지(관리자 화면과 같은 CSP + `connect-src https://*.upload.vimeo.com`)에서 30MB를 5MB씩 PATCH → 중간에 끊고 다시 눌러 남은 위치부터 이어 올려 끝까지 완료 (사용자 확인) |
| 주의 | 가짜 업로드 번호로 보낸 사전 요청은 `401`에 CORS 헤더가 없다. 링크가 만료되면 브라우저에서는 "네트워크 오류"로만 보일 수 있다 → 화면은 연속 실패 시 관문에 업로드 상태를 묻는다(`adminVideoFinish`) |

- 시험용 Vimeo 영상 1개(`[삭제 필요] CORS 시험 2026-10-29`)가 Vimeo 최상위에 남아 있다. Vimeo 화면에서 손으로 지운다.
- 따라서 `admin.html` CSP `connect-src`에 `https://*.upload.vimeo.com`을 더한다.

## 2. 설계와 달라진 점 (사용자 합의 2026-10-29)

### 2-1. 「삭제 대기」 폴더로 옮기지 않는다 → 제목에 `[삭제 필요]`만 붙인다
- 이미 있는 영상을 다른 폴더로 넣는 요청은 Vimeo `interact` 권한이 필요하다(기존 업로드 프로그램 10-06 시험). 지금 토큰 권한(public·private·create·edit·upload)에는 없다.
- 그래서 `admin.md` 7-3 삭제와 7-4 실패 처리 모두 **제목 앞에 `[삭제 필요]`를 붙이는 것까지만** 한다. 영상은 원래 폴더에 그대로 있다.
- 지울 영상 목록은 「관리기록」에서 찾는다(작업 `자료 삭제`의 새 값에 `vimeo: '[삭제 필요] 표시'`, 작업 `영상 정리`). 운영진이 Vimeo 화면에서 `[삭제 필요]`로 검색해 지운다.
- 나중에 `interact` 권한이 있는 토큰으로 바꾸면 폴더 이동을 더할 수 있다.

### 2-2. 영상번호는 한 번에 정하고 잠시 잡아 둔다
- 업로드 중인 영상은 아직 「자료」에 없어서, 다음 번호를 「자료」만 보고 정하면 같은 칸에 여러 파일을 올리거나 두 사람이 동시에 올릴 때 `_01`이 겹친다.
- `adminVideoCreate`는 **고른 파일 전체**를 한 요청으로 받아 번호를 함께 정하고, 정한 번호를 Script Properties(`MEDIA_RESERVED`)에 **24시간** 기록한다. 다음 번호 = 「자료」 파일명과 잡아 둔 번호 중 가장 큰 번호 + 1. `adminVideoFinish`가 등록하면 그 번호의 기록을 지운다.

### 2-3. 영상 추가는 워크숍만 연다
- 멘토링·캠프의 Vimeo 폴더 이름이 정해지지 않았다(확인 필요 ②). 멘토링·캠프는 보기·수정·삭제만 되고 [영상 추가]는 막는다.

## 3. 구현하며 정한 점

### 3-1. Vimeo 폴더 찾기 (읽기 전용 확인 2026-10-30)
- 토큰 권한 실측: `private create edit upload public` (`interact`·`delete` 없음 → 2-1 확인).
- `GET /me/projects`가 **하위 폴더까지 모두**(23개) 돌려주고, 폴더마다 `metadata.connections.parent_folder.uri`로 상위 폴더를 알 수 있다. → 관문은 이 목록 한 번으로 「이름 + 상위 폴더」가 맞는 폴더를 위에서부터 따라가고, 없는 단계만 만든다(`parent_folder_uri`). 같은 이름 폴더가 두 번 생기지 않게 폴더 만들기는 쓰기 잠금 안에서 한다.
- **분야 폴더 이름은 시트 분야명과 다르다**: Vimeo에는 `음악` · `무용` · **`전통`** · `미술`(시트는 `전통예술`). 관문은 `전통예술 → 전통`으로 바꿔 찾는다.
- 날짜 폴더는 `MM-DD (요일)` (`08-07 (금)`).

### 3-2. `apps-script/Vimeo.js` (2026-10-30)
- **새 오류 코드 `VIMEO_ERROR`** — 토큰이 없거나 Vimeo가 거절·설정 확인 실패. 화면(`admin-media.js`)이 "Vimeo 연결에 문제가 있습니다"로 안내한다. `admin-app.js` 공통 문구 표에는 없어 다른 탭에서는 `SERVER_ERROR` 문구로 보인다(공통 표에 넣을지는 합칠 때 결정). 자세한 원인은 Apps Script 실행 기록에만 남긴다.
- 「영상 허용 도메인」은 **쉼표로 여러 개** 적을 수 있게 했다(주소 이전 중 옛 도메인을 함께 둘 때). 비면 `kartsproject.github.io`.
- 설정 확인(공개 설정·폴더·허용 도메인)이 기대와 다르면 「자료」에 등록하지 않는다.
- 「자료」 링크 값이 Vimeo 주소에 들어가므로 숫자 ID만 받는다(아니면 `INVALID_INPUT`).
- 업로드할 때 공개여부 기본값은 **`공개`**(사용자 확인 2026-10-30). 파일마다 바꿀 수 있다.

### 3-3. `apps-script/AdminMedia.js` (2026-10-30)
| 요청 | 받는 값 → 돌려주는 값 |
|---|---|
| `adminMaterials` | `{ program: 'ws'\|'mt'\|'camp' }` → `{ sessions, materials(시트 열 이름 + _row), linkUses(세 시트의 링크별 줄 수), pending(업로드 중), canUpload }` |
| `adminMaterialUpdate` | `{ program, row, before, changes: { 소제목?, 공개여부? } }` — 공개여부는 `공개`·`비공개`만, 소제목 40자 이내 |
| `adminMaterialDelete` | `{ program, row, before }` → `{ vimeo, remaining }` |
| `adminVideoCreate` | `{ program, sessionId, files: [{ name, size }] }` → `{ items: [{ videoId, uploadLink, fileName }], folder }` |
| `adminVideoFinish` | `{ program, videoId, subtitle, visibility, student?: { name, studentId } }` → `{ done: true }` 또는 아직 업로드 중이면 `{ done: false, uploadStatus }` / `{ program, videoId, cancel: true }` → 취소 |

- **취소도 `adminVideoFinish`로 받는다** (`cancel: true`). 새 요청 이름을 만들면 `Admin.js`를 고쳐야 해서.
- **업로드 중인 영상**은 Script Properties `MEDIA_PENDING_{Vimeo 번호}`에 둔다(세션ID·파일명·번호·폴더·원래 파일명·만든 관리자 코드·만료). `adminVideoFinish`는 여기 있는 영상만 받아, 화면이 다른 영상 번호나 파일명을 꾸며 보낼 수 없다.
- **「관리기록」 작업에 `영상 정리` 추가** — 업로드 취소·실패, 여러 파일 중 생성 실패, 24시간 지난 업로드에 `[삭제 필요]`를 붙일 때.
- 「자료」 영상 행의 「비고」에 `관리자 페이지에서 올림 · 원래 파일: {원래 파일명}`을 적는다(기존 규칙: 비고에 원본 위치, 사이트로 내보내지 않음).
- 학생 작품 2줄 등록: 두 번째 줄은 세션ID 비움 · `작품(영상)` · 같은 파일명·링크 · 학생명(·학생ID) · 분야(그 칸의 분야).
- 받는 확장자: mp4·mov·m4v·mkv·avi·mts·webm, 한 번에 20개까지.
- 시험: 가짜 Apps Script·Vimeo 환경 20가지 통과(번호 이어 매김·폴더 재사용·없는 단계만 생성·전통 폴더·충돌·수식 주입·통녹화 삭제·취소·만료 정리·여러 파일 중 실패 정리·설정 확인 실패 시 미등록 등). 실제 Vimeo·시트 시험은 합친 뒤 원래 폴더에서. 경로: `K예술영재 아카이브 › 2026 워크숍 › {분야 폴더} › {MM-DD (요일)}`. 연도 부분은 「설정」 `사업연도`를 쓴다.

### 3-3-1. 학생 작품 영상의 파일명·폴더는 칸 규칙을 따른다 (사용자 결정 2026-10-30)
- 관리자 페이지에서 [학생 작품으로도 등록]을 골라도 파일명은 **칸 규칙**(`{세션ID}_{번호}`), Vimeo 폴더는 **날짜 폴더**다. 「자료」는 8.21 연주회와 같은 2줄(칸의 `영상` + `작품(영상)`).
- 기존 학생 영상과 다른 점: 학생 단위 영상 48개(10-06)와 8.21 연주회 25개(10-28)는 work 규칙 이름(`26-ws-music-work-0821-001`, 가나다순)이고, 연주회 25개는 Vimeo 「음악 › 학생 영상」 폴더에 있다.
- 그대로 두는 이유: 사이트는 링크·세션ID로 연결하고 화면 제목은 소제목(학생명)이라 기능 차이가 없다. 나중에 한 명씩 추가하면 가나다순 번호는 어차피 지킬 수 없다. 이름만 보고 어느 칸 영상인지 알 수 있다.
- 칸에 속하지 않는 학생 영상(「작품(영상)」 1줄만)은 관리자 페이지에서 올릴 수 없다(칸을 골라야 올림). 필요하면 기존처럼 PC 프로그램·TSV로 넣는다.

### 3-4. 화면 `site/js/admin-media.js` · `admin.css` 영상 관리 구역 · `admin.html` CSP (2026-10-30)
- 위: 프로그램 선택 · 분야 버튼 · [새로고침]. 고른 값은 `sessionStorage`에만 둔다.
- 워크숍은 열람 일정표와 같은 격자(`view-schedule.js`는 관리자 페이지에 실리지 않아 그리는 방법만 따라 만들고 `style.css` 칸 스타일을 그대로 씀). 관리자는 **영상이 없는 칸도 누를 수 있다**(추가하려고). 칸에 `영상 N · 미공개 N`(미공개 = 비공개 + 검수대기), `올리는 중 N`. 멘토링·캠프는 일자·시간 순 목록 표.
- 칸을 누르면 아래에 그 칸의 「영상」 행: 파일명 · 소제목(입력칸) · 공개여부(공개/비공개, 지금 값이 검수대기면 그대로 보이고 바꿀 때만 저장) · Vimeo 번호 · [저장] [삭제]. 학생 작품(`작품(영상)`) 행은 세션ID가 없어 칸 목록에 나오지 않는다.
- [영상 추가]: 파일 여러 개 → 파일마다 소제목 · 공개여부(기본 `공개`) · [학생 작품으로도 등록]+학생명(소제목이 비어 있으면 학생명으로 채움) → [N개 올리기].
- 올리기: 위쪽 「올리기」 상자에 파일마다 진행률. **한 파일씩 차례로**, 16MB 조각. 인터넷이 끊기면 다시 연결될 때까지 기다렸다가 서버가 받은 위치부터 잇고, 인터넷은 되는데 10번 연달아 실패하면 멈추고 [다시 시도]·[취소]. 다 올리면 `adminVideoFinish`(Vimeo가 아직 「완료」가 아니면 4초 간격으로 8번까지 다시).
- 업로드 중에는 5분마다 `adminPing`, 창을 닫거나 새로고침하면 경고. **새로고침·창 닫기·로그아웃 뒤에는 이어 올릴 수 없다**(파일을 다시 읽을 수 없음) → 그 영상은 24시간 뒤 관문이 `[삭제 필요]`를 붙인다. 칸 목록에는 「등록되지 않은 업로드 N개」로 보인다.
- 시험: 가짜 관문·가짜 tus 서버 + 헤드리스 브라우저로 로그인 → 일정표 → 칸 → 소제목·공개여부 저장 → 삭제(다른 줄 안내) → 2개 업로드(학생 작품 2줄) → 멘토링 추가 막힘 → 모바일 너비 가로 넘침 없음, 콘솔 오류 없음. 소제목에 HTML을 넣어도 글자 그대로 보이는 것 확인.

## 4. 합칠 때 원래 폴더에서 할 일
- `clasp push` 후 **다시 배포 + 권한 다시 승인**: 관문이 처음으로 `UrlFetchApp`(외부 요청)을 쓰므로 편집기에서 한 번 실행해 권한을 승인해야 한다.
- Script Properties에 `VIMEO_TOKEN`을 사용자가 직접 넣는다(파일에 쓰지 않음).
- 「설정」 탭 `영상 허용 도메인`(비어 있으면 `kartsproject.github.io`). 2026-10-30 저장소가 kartsproject로 옮겨져 사이트 주소가 `https://kartsproject.github.io/archive/`(관리자 `…/archive/admin.html`)가 됐다. 새로 올리는 영상은 이 도메인을 허용 도메인으로 등록한다.
- 기존 문서에 옛 주소가 남아 있다: `docs/admin.md` 11행(관리자 주소)·128행(허용 도메인 기본값). 합칠 때 함께 고친다.
- **이미 올린 영상**(기존 업로드 프로그램으로 올린 440건 등)은 허용 도메인이 `kartsgifted.github.io`뿐이라 새 주소에서 재생되지 않을 수 있다. 일괄 등록이 필요한지 **확인 필요**(이번 작업 범위 밖).
