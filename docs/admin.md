# 관리자 페이지 설계

> 2026-10-29 사용자와 합의한 설계. 구현 중 달라지는 점은 이 문서와 `docs/decisions.md`를 함께 고친다.

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 주소 | `kartsproject.github.io/archive/admin.html` (열람 화면에서 링크하지 않음) |
| 방식 | 관리자가 로그인하면 **관문이 대신 시트를 고친다.** 시트를 직접 고치는 방법도 그대로 쓸 수 있다 |
| 로그인 | 열람 사이트와 같은 **접근코드** 방식. 「접근코드」 탭 「권한」이 `관리자`인 코드만 들어온다 |
| 권한 | 관리자는 **모두 같은 권한**(인원 미정) |
| 기능 | ① 접근코드 추가·수정·정지 ② 접속 기록 보기 ③ 일정표 칸별 영상 보기·변경·삭제·추가 |
| 영상 추가 전제 | **항상 편집된 영상**. 압축하지 않고 그대로 Vimeo에 올린다. 압축이 필요한 통녹화 원본은 지금처럼 PC 프로그램으로 처리하고 관리자 페이지에서 다루지 않는다 |
| 진행 순서 | 0단계 공통 기반 → 1단계 접근코드·접속 기록 / 2단계 영상 관리 (1·2단계는 병렬 가능, 9절) |

## 2. 화면

- `site/admin.html` 한 장. 로그인 → 탭 3개 **[접근코드] [접속 기록] [영상 관리]**.
- 파일: `site/js/admin-app.js`(로그인·탭 전환·토큰) · `admin-codes.js` · `admin-logs.js` · `admin-media.js`. 관문 호출은 `site/js/api.js`의 `callGateway`·`getDeviceId`를 그대로 쓴다.
- 관리자 토큰은 열람 토큰과 다른 키(`karts_admin_token`)로 `sessionStorage`에 둔다. 같은 브라우저에서 열람 사이트와 섞이지 않게 하기 위함.
- PC 화면 기준. 모바일은 깨지지 않을 정도만.
- 모든 외부 값(코드 이름, 로그의 이름, 소제목 등)은 `textContent`로 출력한다.
- `noindex` 메타, `robots.txt`는 이미 전체 차단.

## 3. 로그인·권한

| 항목 | 규칙 |
|---|---|
| 시트 | 「접근코드」 탭에 **「권한」 열** 추가. 값 `열람` · `관리자`, 비어 있으면 `열람` |
| 요청 | `adminAuth` — 기존 `auth`와 같은 검증(코드·상태·사용기한·기기 잠금) + 권한이 `관리자`인지 확인. 관리자가 아니어도 `AUTH_INVALID`로만 답한다(열람 코드가 맞다는 사실을 알려 주지 않음) |
| 관리자 토큰 | 서명 내용에 `role: 'admin'`을 넣는다. **30분**, 관리 요청마다 새 토큰을 함께 돌려줘 사용 중에는 이어진다 |
| 매 요청 검증 | 토큰 서명·만료·버전 + `role` + **지금 시트의 권한이 여전히 `관리자`인지**. 시트에서 권한을 내리거나 정지하면 바로 막힌다 |
| 열람 토큰 | 관리 요청에 쓰면 거절(`TOKEN_INVALID`) |
| 관리자 코드로 열람 사이트 | 들어갈 수 있다(전체 열람) |
| 실패 제한 | 기존 기기별 잠금(5회·10분)을 같이 쓴다. 로그 「요청」 값은 `adminAuth` |
| 권고 | 관리자 코드는 열람 코드보다 길게(12자 이상) 만들고 따로 보관한다 |
| 자기 잠금 방지 | 지금 로그인한 관리자 코드 자신은 관리자 페이지에서 정지·권한 변경할 수 없다(시트에서는 가능) |

## 4. 쓰기 공통 규칙

모든 관리 요청(쓰기)은 아래를 지킨다.

1. **잠금** — `LockService`로 한 번에 하나씩 쓴다.
2. **수식 주입 방지** — 시트에 쓰는 값은 `sanitizeForSheet_`를 거친다(`=` `+` `-` `@` 앞에 `'`).
3. **저장 직전 확인** — 화면은 행 번호와 함께 **읽었을 때의 값**을 보낸다. 관문은 그 행이 그대로일 때만 쓰고, 다르면 `CONFLICT`로 거절한다 → 화면은 "시트가 바뀌었습니다. 새로고침 후 다시 해 주세요". 시트를 직접 고치는 중에 엉뚱한 행을 덮어쓰지 않기 위함.
4. **캐시** — 쓰고 나면 `bumpCacheVersion_()`. 「캐시 비우기」를 따로 누를 필요가 없다.
5. **관리기록** — 공통 시트 새 탭 **「관리기록」**(자동, 잠금)에 한 줄 남긴다.

| 열 | 내용 |
|---|---|
| 일시 | |
| 코드 | 작업한 관리자 코드 |
| 이름 | 관리자가 로그인 때 입력한 이름 |
| 작업 | 코드 추가 · 코드 수정 · 접속 끊기 · 자료 수정 · 자료 삭제 · 영상 추가 · 영상 정리(업로드 취소·실패, 24시간 지난 업로드에 `[삭제 필요]`를 붙일 때) |
| 대상 | 접근코드 / `{프로그램} › 자료` + 세션ID·파일명 |
| 이전 값 | 바꾸기 전 행 전체(JSON). **지운 행도 여기 남아 복구 근거가 된다** |
| 새 값 | 바꾼 뒤 행 전체(JSON) |

## 5. 1단계 — 접근코드

| 기능 | 규칙 |
|---|---|
| 목록 | 코드 · 이름(주체) · 배포 대상 · 첫 화면 · 사용기한 · 상태 · 권한 · 버전 · 비고 |
| 추가 | 이름(주체) 필수. 배포 대상·첫 화면·사용기한·권한을 고른다. 코드는 **자동 생성**(`KA-{대상}-{4자}`, 헷갈리는 글자 `0 O 1 I L` 제외) 또는 **직접 입력**(기억하기 쉬운 짧은 코드처럼). 대문자·숫자·`-`만, 4~20자(로그인 입력칸 최대 20자). 중복이면 거절. 버전 1, 상태 `사용` |
| 수정 | 이름·배포 대상·첫 화면·사용기한·상태(`사용`/`정지`)·권한·비고. **코드 글자를 바꾸면 버전도 올려** 옛 코드로 받은 접속을 끊는다 |
| 접속 끊기 | 버전 +1. 그 코드로 들어와 있는 사람은 다음 요청에서 다시 로그인해야 한다 |
| 삭제 | 하지 않는다. **정지**로 대신한다(지난 접속 기록이 어느 주체 것인지 남기기 위함) |
| 첫 화면 | `분야 선택` · `음악` · `무용` · `전통예술` · `미술` 중 고른다(분야 이름이 있으면 그 분야로 바로 감 — 기존 규칙) |
| 자동 생성 모양 | 화면이 미리 넣어 주고 고칠 수 있다. 관리자 권한이면 `KA-ADMIN-{6자}`(15자), 그 밖에는 배포 대상에 따라 `KA-STAFF/MUSIC/DANCE/TRAD/ART-{4자}`, 목록에 없는 대상은 `KA-CODE-{4자}` |
| 관리자 코드 길이 | 3절 권고를 **규칙으로** 적용 — 권한이 `관리자`면 12자 미만은 저장하지 않는다(구현 2026-10-29) |
| 예전 값 | 손으로 넣은 예전 값(목록 밖 상태 등)은 그 칸을 바꾸지 않는 한 그대로 둔다 |
| 구현 | `apps-script/AdminCodes.js` · `site/js/admin-codes.js` |

| 방금 접속 | 성공 기록은 모았다가 1분마다 쓰지만(Log.js), 조회할 때 먼저 모아 둔 기록을 써서 방금 접속도 바로 보인다 |
| 구현 | `apps-script/AdminLogs.js` · `site/js/admin-logs.js` |

## 7. 2단계 — 영상 관리

### 7-1. 보기
- 프로그램·분야를 고르면 **관리자용 일정표**가 나온다. 워크숍은 열람 일정표와 같은 격자이고, **비공개 자료도 보인다**. 칸에 `영상 N · 미공개 N`(미공개 = 비공개 + 검수대기)과 `올리는 중 N`을 표시한다. 멘토링·캠프는 일자·시간 순 목록 표.
- 관리자는 **영상이 없는 칸도 누를 수 있다**(추가하려고). 칸을 누르면 아래에 그 칸의 「영상」 행 목록(파일명 · 소제목 · 공개여부 · Vimeo 번호). 학생 작품(`작품(영상)`) 행은 세션ID가 없어 칸 목록에 나오지 않는다.
- 요청 `adminMaterials` { program } — 그 프로그램 시트의 「일정」·「자료」 전체(비공개 포함, 행 번호 포함), 세 시트의 링크별 사용 줄 수, 업로드 중인 영상. 캐시를 쓰지 않는다.
- 고른 프로그램·분야는 `sessionStorage`에만 둔다.

### 7-2. 변경
- **소제목**(40자 이내), **공개여부**(`공개`/`비공개`)를 고친다. 요청 `adminMaterialUpdate`. 지금 값이 `검수대기`면 그대로 보이고, 바꿀 때만 저장한다.
- Vimeo 제목은 바꾸지 않는다(파일명과 같게 유지).

### 7-3. 삭제
- 「자료」 행을 지운다. 요청 `adminMaterialDelete`. 지운 행 전체가 「관리기록」에 남는다.
- **Vimeo 영상**은 같은 링크를 쓰는 행이 세 프로그램 시트 어디에도 남아 있지 않을 때만 Vimeo 제목 앞에 `[삭제 필요]`를 붙인다. 영상은 원래 폴더에 그대로 둔다. 남아 있으면(통녹화를 여러 칸에 등록한 경우) 아무것도 하지 않는다.
- **영구 삭제·폴더 이동은 하지 않는다.** 토큰에 삭제(`delete`)·폴더 넣기(`interact`) 권한이 없고(`docs/decisions.md` 9절 「업로드 이어 하기」 ④), 영구 삭제는 되돌릴 수 없기 때문. 운영진이 Vimeo 화면에서 `[삭제 필요]`로 검색해 지운다. 지울 목록은 「관리기록」의 `자료 삭제`·`영상 정리`에서도 찾을 수 있다. (처음 설계는 「삭제 대기」 폴더로 옮기기였으나 권한 때문에 바꿈, 2026-10-29)
- 확인 창에 "이 영상은 다른 칸 N곳에도 등록되어 있습니다"를 보여 준다.

### 7-4. 추가 (편집된 영상)

```
칸 선택 → 파일 선택 → [관문] Vimeo에 빈 영상 생성 → [브라우저] Vimeo로 직접 전송 → [관문] 설정 확인·「자료」 등록·캐시 비우기
```

1. 관리자 일정표에서 **칸을 누르고 [영상 추가]**. 칸이 분야·프로그램·날짜·시간(세션ID)을 정한다. 일정표에 없는 칸에는 추가할 수 없다. **지금은 워크숍만 열고**, 멘토링·캠프는 보기·수정·삭제만 된다(Vimeo 폴더 이름 미정).
2. 파일을 여러 개 고른다(한 번에 20개까지, mp4·mov·m4v·mkv·avi·mts·webm. 드라이브 데스크톱 앱의 `G:` 공유 폴더 파일도 고를 수 있음). 파일마다 **소제목**과 **공개여부**(기본 `공개`, 사용자 확인 2026-10-30)를 적는다. **[학생 작품으로도 등록]**을 고르고 학생명을 적으면 「작품(영상)」 행도 함께 만든다(8.21 연주회와 같은 2줄 방식). 소제목이 비어 있으면 학생명으로 채운다.
3. `adminVideoCreate` — 고른 파일 전체를 한 요청으로 받는다. 관문이 파일명을 정하고(`{세션ID}_{영상번호}`, `docs/sheet-schema.md` 9절), Vimeo에 빈 영상을 만든다. 숨김·사이트 도메인에서만 재생·내려받기 차단과 폴더(`K예술영재 아카이브 › {사업연도} 워크숍 › {분야 폴더} › {MM-DD (요일)}`, 없는 단계만 만듦)를 이때 함께 정한다. 화면에는 **업로드 주소만** 돌려준다.
4. 브라우저가 업로드 주소로 파일을 **한 파일씩 차례로**, 16MB 조각으로 보낸다(tus). 진행률을 보여 주고, 인터넷이 끊기면 다시 연결될 때까지 기다렸다가 받은 위치부터 잇는다. 인터넷은 되는데 10번 연달아 실패하면 멈추고 [다시 시도]·[취소]를 보여 준다. 업로드 중에는 5분마다 `adminPing`으로 토큰을 잇고, 창을 닫으려 하면 경고한다.
5. `adminVideoFinish` — 관문이 Vimeo에 업로드 완료를 확인하고, 허용 도메인을 등록하고, 설정을 다시 확인한 뒤 「자료」에 행을 추가하고 캐시를 비운다. Vimeo가 아직 「완료」가 아니면 화면이 4초 간격으로 8번까지 다시 묻는다.
6. Vimeo가 재생용 변환을 마칠 때까지(몇 분) 사이트에서 바로 재생되지 않을 수 있다.

| 항목 | 규칙 |
|---|---|
| Vimeo 토큰 | 관문 Script Properties `VIMEO_TOKEN`에만 둔다. 브라우저로 보내지 않는다. 값은 사용자가 직접 넣는다(파일에 쓰지 않음). 권한은 `public private create edit upload`(`interact`·`delete` 없음) |
| 허용 도메인 | 「설정」 탭 「영상 허용 도메인」, **쉼표로 여러 개** 적을 수 있다(주소 이전 중 옛 도메인을 함께 둘 때). 비어 있으면 `kartsproject.github.io` |
| 분야 폴더 | Vimeo 분야 폴더 이름은 `음악` · `무용` · **`전통`** · `미술`. 관문이 시트의 `전통예술`을 `전통`으로 바꿔 찾는다. 폴더는 `GET /me/projects` 한 번으로 이름 + 상위 폴더를 따라가고, 같은 폴더가 두 번 생기지 않게 쓰기 잠금 안에서 만든다 |
| 영상번호 | 다음 번호 = 「자료」 파일명과 **잡아 둔 번호** 중 가장 큰 번호 + 1. 정한 번호는 Script Properties `MEDIA_RESERVED`에 24시간 잡아 둔다(업로드 중인 영상은 아직 「자료」에 없어 여러 파일·동시 업로드에서 번호가 겹치지 않게) |
| 업로드 중 기록 | Script Properties `MEDIA_PENDING_{Vimeo 번호}`(세션ID·파일명·번호·폴더·원래 파일명·만든 관리자 코드·만료). `adminVideoFinish`는 여기 있는 영상만 받으므로 화면이 다른 번호·파일명을 꾸며 보낼 수 없다 |
| 학생 작품 파일명 | [학생 작품으로도 등록]이어도 파일명은 **칸 규칙**(`{세션ID}_{번호}`), 폴더는 날짜 폴더(사용자 결정 2026-10-30). 기존 학생 영상(work 규칙 이름, 「학생 영상」 폴더)과 다르지만 사이트는 링크·세션ID로 연결하므로 기능 차이가 없다. 칸에 속하지 않는 학생 영상은 관리자 페이지에서 올리지 않는다(기존처럼 PC 프로그램·TSV) |
| 「비고」 | 영상 행에 `관리자 페이지에서 올림 · 원래 파일: {원래 파일명}` (사이트로 내보내지 않음) |
| 링크 값 | 「자료」 링크가 Vimeo 주소에 들어가므로 숫자 ID만 받는다(아니면 `INVALID_INPUT`) |
| 설정 확인 실패 | 공개 설정·폴더·허용 도메인이 기대와 다르면 「자료」에 등록하지 않는다 |
| 실패 처리 | 등록 전에 실패·취소한 Vimeo 영상, 24시간 지난 업로드는 제목 앞에 `[삭제 필요]`를 붙인다(폴더는 옮기지 않음, 7-3). 「관리기록」 작업 `영상 정리` |
| 이어 올리기 한계 | 새로고침·창 닫기·로그아웃 뒤에는 이어 올릴 수 없다(파일을 다시 읽을 수 없음). 그 영상은 칸 목록에 「등록되지 않은 업로드 N개」로 보이고, 24시간 뒤 관문이 `[삭제 필요]`를 붙인다 |
| 화면 보안 정책 | `admin.html`의 `connect-src`에 `https://*.upload.vimeo.com` |
| 확인 결과 | ① 브라우저에서 Vimeo 업로드 주소로 직접 보내기: **가능**(2026-10-29, 사전 요청·이어 올리기까지 확인) |
| **확인 필요** | ② 워크숍 외 프로그램(멘토링·캠프)의 Vimeo 폴더 이름 → 정해지면 영상 추가를 연다 |
| 구현 | `apps-script/AdminMedia.js` · `apps-script/Vimeo.js` · `site/js/admin-media.js`. 작업 메모 `docs/admin-media-notes.md` |

## 8. 관문 요청 (추가분)

모두 POST 본문의 `action`으로 구분하고, 응답 형식은 기존과 같다(`docs/api.md` 2절). 관리자 토큰이 필요한 요청은 응답에 새 토큰을 함께 담는다.

| 요청 | 단계 | 용도 |
|---|---|---|
| `adminAuth` | 0 | 관리자 로그인 |
| `adminPing` | 0 | 토큰만 잇기(업로드처럼 관문을 오래 부르지 않을 때) |
| `adminCodes` | 1 | 접근코드 목록 |
| `adminCodeSave` | 1 | 접근코드 추가·수정 |
| `adminCodeRevoke` | 1 | 접속 끊기(버전 +1) |
| `adminLogs` | 1 | 접속 기록 |
| `adminMaterials` | 2 | 프로그램의 일정·자료 전체 |
| `adminMaterialUpdate` | 2 | 소제목·공개여부 수정 |
| `adminMaterialDelete` | 2 | 자료 행 삭제 |
| `adminVideoCreate` | 2 | Vimeo 빈 영상 생성, 업로드 주소 발급 |
| `adminVideoFinish` | 2 | 업로드 확인·설정·「자료」 등록, 업로드 취소(`cancel: true`) |

새 오류 코드: `CONFLICT`(저장 직전 행이 바뀜), `INVALID_INPUT`(형식 오류·중복 코드 등), `NOT_FOUND`, `BUSY`(다른 저장 작업이 잠금을 쥐고 있음), `VIMEO_ERROR`(토큰이 없거나 Vimeo가 거절·설정 확인 실패 → 화면은 "Vimeo 연결에 문제가 있습니다". 자세한 원인은 Apps Script 실행 기록에만).

**영상 관리 요청·응답 모양** (`result` 안의 값)

| 요청 | 받는 값 → 돌려주는 값 |
|---|---|
| `adminMaterials` | `{ program: 'ws'\|'mt'\|'camp' }` → `{ sessions, materials(시트 열 이름 + _row), linkUses(세 시트의 링크별 줄 수), pending(업로드 중), canUpload }` |
| `adminMaterialUpdate` | `{ program, row, before, changes: { 소제목?, 공개여부? } }` |
| `adminMaterialDelete` | `{ program, row, before }` → `{ vimeo, remaining }` |
| `adminVideoCreate` | `{ program, sessionId, files: [{ name, size }] }` → `{ items: [{ videoId, uploadLink, fileName }], folder }` |
| `adminVideoFinish` | `{ program, videoId, subtitle, visibility, student?: { name, studentId } }` → `{ done: true }`, 아직 업로드 중이면 `{ done: false, uploadStatus }` / **취소**는 `{ program, videoId, cancel: true }`(새 요청 이름을 만들지 않으려고 같은 요청으로 받음) |

**응답 모양** — `adminAuth`는 `{ token, expiresAt, name, label }`(label = 코드의 「이름」). 나머지 관리 요청은 `{ result, session: { token, expiresAt } }`이고, 화면은 `session`의 새 토큰으로 바꿔 끼운다.

## 10. 0단계에서 만든 공통 부품 (1·2단계는 이것만 써서 만든다)

### 관문 (`apps-script/Admin.js`)

| 함수 | 쓰임 |
|---|---|
| 처리 함수 계약 | `function adminXxx_(req, admin)` — 반환값이 `data.result`로 나간다. 실패는 `throw adminError_('CONFLICT')`처럼 던진다. 그 밖의 예외는 `SERVER_ERROR`. `admin`은 `{ code, name, row }` |
| `adminHandlerFor_` | 요청 이름 → 처리 함수. **8절의 모든 요청이 이미 들어 있다** — 각 단계는 처리 함수만 자기 파일에 정의하면 된다(이 파일을 고칠 필요 없음) |
| `adminWrite_(work)` | 쓰기 작업을 잠금 안에서 실행하고 끝나면 캐시 버전을 올린다. 잠금을 10초 안에 못 잡으면 `BUSY` |
| `readAdminTable_(탭, program)` | 탭 전체를 캐시 없이 읽어 `{ sheet, headers, rows }`. 각 행은 `{ _row: 시트 행 번호, 열 이름: 글자 }`. program을 빼면 공통 시트 |
| `checkRowUnchanged_(sheet, headers, row, before)` | 저장 직전 확인. before의 열이 지금도 같으면 지금 행을 돌려주고, 아니면 `CONFLICT` |
| `writeRowChanges_(sheet, headers, row, changes)` | 바꾼 열만 쓴다(수식 주입 방지 포함). 없는 열 이름이면 `INVALID_INPUT` |
| `appendRowObject_(sheet, headers, obj)` | 머리글 순서대로 맨 아래에 한 줄 추가, 행 번호 반환 |
| `recordAdminAction_(admin, 작업, 대상, 이전, 새)` | 「관리기록」 한 줄. 이전·새 값은 객체를 그대로 넘기면 JSON으로 적는다 |
| `cellText_(값)` | 시트 값 → 글자(날짜 `yyyy-MM-dd`, 시각 `HH:mm`) |

쓰기 처리 함수의 기본 모양:

```js
function adminCodeSave_(req, admin) {
  return adminWrite_(function () {
    var t = readAdminTable_('접근코드');
    var before = checkRowUnchanged_(t.sheet, t.headers, req.row, req.before);
    writeRowChanges_(t.sheet, t.headers, req.row, req.changes);
    recordAdminAction_(admin, '코드 수정', before['코드'], before, req.changes);
    return { ok: true };
  });
}
```

### 화면 (`site/js/admin-app.js`)

| 함수 | 쓰임 |
|---|---|
| `registerAdminTab(id, { render, onShow })` | 탭 붙이기. id는 `codes` · `logs` · `media`. render(container)는 처음 열 때 한 번, onShow(container)는 열 때마다 |
| `adminCall(action, payload, { write })` | 관리 요청. `result`만 돌려주고 새 토큰은 알아서 바꿔 낀다. **쓰기는 반드시 `{ write: true }`** — 예비 요청을 보내지 않아 두 번 저장되지 않고 90초까지 기다린다. 토큰이 끝나면 로그인 화면으로 돌아간다 |
| `adminErrorMessage(e, { write })` | 오류 코드 → 안내 문구 |
| `showAdminToast(문구, 'ok' \| 'error')` | 화면 아래 알림 |
| `openAdminDialog({ title, body, okLabel, danger, validate })` | 확인 창. 확인을 누르면 `true`로 끝나는 Promise. body는 문자열 또는 DOM 노드. validate()가 문구를 돌려주면 창을 닫지 않고 그 문구를 보여 준다(입력 양식용, 1단계에서 추가) |
| `adminPlaceholder(문구)` | 빈 상태 안내 상자 |

### 시트 준비 (`apps-script/Setup.js` `setupAdminSheets()`)
편집기에서 한 번 실행하면 「접근코드」에 「권한」 열(선택 목록 열람/관리자)이 붙고 「관리기록」 탭이 생긴다. **첫 관리자 코드는 시트에서 직접** 한 줄 만들고 「권한」을 `관리자`로 둔다.
